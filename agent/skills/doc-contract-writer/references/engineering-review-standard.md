# 개발 단계별 필수 검토 기준

정책 버전: `fivecircles-engineering-v1` · 2026-11-03

각 차원을 반드시 검토하고 코드/계약/테스트의 위치를 근거로 남긴다. 파일이 짧다거나
테스트가 많다는 사실만으로 통과시키지 않는다. 실제 범위에서 확인하지 못한 것은 UNKNOWN이다.

## 1. 리소스 효율

- CPU/메모리/디스크·네트워크 I/O, 모델 토큰/비용, 지연과 동시성의 주요 경로를 확인한다.
- 불필요한 반복 읽기·해시·파싱·API 호출·N+1·무제한 재시도/대기/캐시를 찾는다.
- 캐시/재사용이면 키·격리 범위·수명·무효화·최대 크기와 오래된 값/동시 요청 영향을 확인한다.
- 성능 주장은 입력 규모·호출 횟수·측정 환경·검증 근거를 붙인다. 측정하지 않은 효과는 추정이다.
- 작은 개발 단계에 불필요한 인프라·추상화 비용을 강요하지 않는다. 가장 단순한 유효 개선을 제안한다.

## 2. 보안 도입 단계 판단

먼저 `LOCAL_PROTOTYPE / SHARED_DEV / EXTERNAL_BETA / PRODUCTION / UNKNOWN` 중 현재 단계와
다음 예정 단계를 실제 접근 경로·사용자·실데이터·자격증명·부작용 근거로 판단한다.
이름이 dev/MVP라도 실사용자/공개 접근/실데이터가 있으면 그 노출 수준으로 판단한다.

- **NOW_REQUIRED**: 현재 노출로 이미 필요한 통제. 실제 비밀값 비노출, 실데이터의 접근 경계,
  외부 입력에 의한 실행/파일 경로 접근, 파괴적 쓰기나 중복 과금 같은 현재 발생 가능한 위험을 본다.
  프로토타입이라는 이유만으로 현재 필요한 최소 통제를 일괄 연기하지 않는다.
- **DEFERRED_UNTIL**: 지금 구현 비용이 더 크고 현재 노출에서 필요하지 않은 강화.
  연기 이유·현재 임시 통제·적용할 단계/정확한 트리거·책임 역할·완료 기준을 반드시 쓴다.
  예: 외부 베타 공개 전 권한별 통합 테스트, 실제 운영 전 회전/감사/복구 절차.
  특정 통제를 모든 프로젝트에 일괄 요구하지 않는다.
- **RECOMMENDED_NOW**: 현재 위험을 줄이는 작고 유효한 보강안과 검증 방법을 제시한다.
- **NOT_APPLICABLE / UNKNOWN**: 비해당 근거 또는 부족한 노출 정보와 확인할 항목.

보안 제안은 위협·현재 도달 가능 경로·영향·최소 조치로 설명한다. 미래 운영의 모든 보안을
초기 개발의 차단 조건으로 만들지 않는다. 반대로 이미 노출된 위험은 일정만으로 면제하지 않는다.

## 3. Conciseness와 중복

- 같은 책임의 반복 로직, 중복 검증·변환·설정·캐시·상태 저장과 불필요한 wrapper/분기를 찾는다.
- 기존 공통 함수/계약으로 합칠 수 있는지 확인한다. 줄 수보다 책임과 변경 이유가 일치하는지가 우선이다.
- 호환성 어댑터·독립 테스트 fixture 등 의도적 중복은 이유를 남긴다. 다른 도메인을 억지로 합치지 않는다.
- 필요 없는 추상화·긴 전달 체인·죽은 코드·서로 다른 이름의 같은 정책을 구체적으로 지적한다.

## 4. 유지보수성과 구조

- 변경 파일 트리와 각 폴더/파일의 소유 책임을 확인한다. 새 파일을 둔 이유와 기존 경계를 설명한다.
- 메서드를 입력/검증, 도메인 판단, I/O·외부 연동, 출력/직렬화, orchestration으로 분류하여
  한 메서드에 섞인 책임·숨은 부작용·공유 mutable state를 찾는다. 불필요한 파일 분리는 하지 않는다.
- 의존 방향·순환·거대 모듈·테스트 경계·실패 원인 추적 가능성을 검토한다.
- 구조 제안은 현 구조에서의 최소 변경과 검증 방법까지 제시한다.

## 5. 호환성과 확장성

- 기존 호출자·DTO·오류/상태·저장 데이터·설정 기본값·구버전 경로가 유지되는지 확인한다.
- 선택 매개변수/공개 인터페이스/확장 지점과 금지 의존성을 명시한다. 새 제공자/기능이 들어갈
  위치와 필요한 변경 범위를 설명하되 아직 필요 없는 plugin framework를 강제하지 않는다.
- 변경이 필요하면 migration/rollout/rollback과 계약 테스트를 계획한다.

## 포니테일 등 외부 레포 참고

구조상 필요한 근거가 있을 때만 참고한다. 사용자 지정 URL/로컬 remote로 저장소 정체와
commit·관련 파일·라이선스를 확인한다. 동명이인 공개 레포를 추정해 쓰지 않는다.
차용할 원리·현재 문제와의 대응·도입 비용·채택/미채택 이유를 기록한다.
코드를 가져오면 라이선스/출처를 보존하고 프로젝트 경계와 계약을 먼저 검증한다.
참조 레포가 미확인이어도 위 5개 차원 자체의 검토를 중단하지 않는다.

## 보고 형식

| 차원 | 판정 | 현재 근거 | 필요한 조치/검증 |
|---|---|---|---|
| 리소스 효율 | PASS/ISSUE/NOT_APPLICABLE/UNKNOWN | 파일:행·측정 | 조치 |
| 단계별 보안 | PASS/ISSUE/DEFERRED/NOT_APPLICABLE/UNKNOWN | 단계·노출 근거 | NOW_REQUIRED와 후기 작업 |
| Conciseness | PASS/ISSUE/NOT_APPLICABLE/UNKNOWN | 중복/책임 근거 | 조치 |
| 유지보수·구조 | PASS/ISSUE/NOT_APPLICABLE/UNKNOWN | 트리·메서드 분류 | 조치 |
| 호환·확장 | PASS/ISSUE/NOT_APPLICABLE/UNKNOWN | 호출자·스키마·테스트 | 조치 |

| 보안 항목 | 분류 | 지금/나중 판단 이유 | 임시 통제 | 적용 단계/트리거 | 책임 역할 | 완료 기준 |
|---|---|---|---|---|---|---|

개선 제안, 현재 결함, 미검증 가정을 구분한다. 지적의 심각도는 실제 도달 가능성·영향으로 판단한다.

코드나 원문을 복사하지 않았으며, 스킬 설치를 전제하지 않는다.

1. 새 구현 전 기존 코드 → 표준/플랫폼 기능 → 이미 설치된 의존성 순으로 재사용 가능성을 확인한다.
2. 기대 입력 규모·동시성에서 N+1, 제곱 복잡도, 무제한 메모리와 프로세스별 중복 작업을 확인한다.
3. 함께 변경돼야 하는 중복만 공통 원인에서 한 번 수정한다. 읽기 어려운 압축은 간결성으로 인정하지 않는다.
4. 파일과 메서드는 독립 업무 책임으로 나눈다. 줄 수만 줄이는 헬퍼나 미래용 추상화는 만들지 않는다.
5. 시그니처·반환값·행동이 바뀌면 diff 밖 호출자·fixture·설정·export까지 영향 범위를 확인한다.

단계별 보안 판단과 파일 트리·메서드 분류표는 사용자 요청에 따른 Fivecircles 추가 기준이다.
Ponytail의 기능이나 절감 효과로 표시하지 않는다. 원본/코드를 추후 복사할 때는
[MIT 고지](https://github.com/DietrichGebert/ponytail/blob/96608e078b2d5ea607c5c3b8b5a54d1c1fba6846/LICENSE)를 보존한다.
