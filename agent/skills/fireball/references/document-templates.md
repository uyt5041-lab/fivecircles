# 파이어볼 문서 최소 템플릿

- 구현자/서명: 희동 (Codex)
- 작성일시: 2026-09-22T15:55:40+09:00
- 최종수정일시: 2026-09-22T15:55:40+09:00

아래 중 해당 문서에 필요한 템플릿만 사용한다. 중괄호는 실제 값으로 채운다.
시간은 현재 시각과 시간대를 사용한다. 작성 시각을 과거 배포/검증 시각으로 대신하지 않는다.

## 공통 서명

```md
- 기능 ID: {ID}
- 입력 문서: {실제 경로와 요구 ID}
- 구현자: {희동 또는 사용자가 지정한 이름}
- 서명: {이름} (Codex 구현자 역할)
- 작성일시: {ISO 8601, 예: YYYY-MM-DDTHH:mm:ss+09:00}
- 최종수정일시: {실제 수정 시각과 시간대}
- 상태: {DRAFT / IN_PROGRESS / IMPLEMENTED / VERIFIED / BLOCKED}
```

## Blueprint

경로: `fivecircles/architecture/{branch name}/blueprint{ID}.md`

```md
# {ID}: {기능명} Blueprint
{공통 서명}
## 목표와 제외 범위
{사용자 입력 -> 기대 결과 / 완료 기준}
## 현재 구조
{Graft 기준 SHA, 노드와 파일:라인, 이미 있음/부분/없음, 실제 연결 경계}
## 구조 결정
{structure-architect 적용 결과, 모듈 책임/파일 배치, 의존 방향, 선택 이유와 대안}
## 재사용과 변경
{기존 API/서비스/테이블 소유권, 변경 파일, 신규 요소가 필요한 이유}
## 검증과 배포
{회귀/실패/복구 시나리오, 데이터·환경 격리, 관측 및 배포·롤백 방법}
## 연결 문서
{원본 audit/request, architecture/contract/{ID}.md, TODO 항목}
```

## Contract

경로: `fivecircles/architecture/contract/{ID}.md`

```md
# {ID}: {기능명} Contract
{공통 서명}
## 적용 범위와 구조 경계
{blueprint 링크, 모듈 public API, 허용/금지 의존, 데이터 소유권}
## 입출력과 상태
{실제 API/tool/DTO/필드명, 입력 검증, 상태 전이, 오류 및 재시도}
## 불변조건
{권한/개인정보/로컬 전용/원본 계보/멱등성/동시성 중 해당 사항}
## 완료 기준과 증거
{조건마다 테스트 또는 사용자 시나리오, 실제 결과 확인법}
## 호환성과 운영
{기존 계약과 차이, 변경/마이그레이션/배포·복구 조건}
```

## TODO 구간

경로: `fivecircles/architecture/todolist.md`

```md
## {ID}: {기능명}
- 구현자/서명: {이름} (Codex)
- 작성일시: {실제 시각과 시간대}
- 최종수정일시: {실제 시각과 시간대}
- 입력 / Blueprint / Contract: {문서 링크}
- [ ] {ID}-1: {작은 구현 단위, 완료 조건, 검증 명령/시나리오}
- [ ] {ID}-2: {회귀/통합 검증, 증거 위치}
- [ ] {ID}-3: 로그올, Graft, 승인된 Git/CI/병합/CD 및 실제 결과 확인
```

## 구현자 로그와 재개 정보

경로: `fivecircles/work/log_{이름}/log_{ID}_{YYYY-MM-DD}.md`

```md
# {ID}: {작업 내용}
{공통 서명}
## 실행 식별
- 저장소/worktree 절대경로: {실제 경로}
- 브랜치 / 기준 브랜치 / 기준 SHA: {실제 값}
- 입력 문서 / 선택된 기능 목록: {범위}
- 현재 단계 / 수정 파일: {작업 상태}
## 결정과 검증
{시각별 결정, 변경 이유, 실행한 명령, 결과/실패/증거; 미실행 명시}
## 전달 상태
- 구현 / 테스트 / 로그올 / Graft: {각 상태와 근거}
- 커밋 / 푸시 / CI / 병합 / CD: {각 상태, SHA/대상/실행 URL}
- 배포 후 health/readback/artifact: {결과 또는 NOT_RUN 사유}
## 다음 한 작업
{TODO ID, 시작 위치, 남은 위험, 승인/환경 조건}
```

전달 단계 상태는 `COMPLETED`, `PENDING`, `NOT_APPLICABLE`, `BLOCKED`로 구분한다.
`NOT_APPLICABLE`에는 변경 범위에 근거한 이유를 남긴다. 권한이 없다는 사유를
배포 비대상으로 바꾸지 않는다. 마지막 상태 기록만으로 실제 명령 실행을 대신하지 않는다.
