# Prompt Optimization Strategy (LLM 프롬프트 고도화 전략)

이 문서는 `intelligence-service` 내 LLM 프롬프트(특히 `refine-fact.txt`)의 성능과 범용성을 개선하기 위한 중장기 전략을 담고 있습니다.

## 1. 동적 Few-Shot Learning 주입 (Context-Aware)
현재 고정된 예시(Generic Examples)를 넘어, 각 드라마의 특성에 맞는 사례를 제공합니다.
- **방안**: 해당 드라마에서 관리자가 최종 승인(Approved)한 고품질 정제 사례 2~3개를 추출하여 프롬프트의 예시 섹션에 동적으로 삽입합니다.
- **기대 효과**: 드라마마다 다른 말투나 고유한 설정(예: 계급 사회, 특수 용어 등)을 AI가 즉석에서 학습하여 정밀도가 향상됩니다.

## 2. 모호성(Ambiguity) 플래그 도입
AI의 '추측 금지' 지침으로 인해 버려지는 유용한 힌트를 보존합니다.
- **방안**: 결과 JSON에 `uncertainty_score` 또는 `is_ambiguous: boolean` 필드를 추가합니다.
- **활용**: AI가 "텍스트 근거는 부족하지만 정황상 누구인 것 같다"고 판단할 경우, 이를 확정 데이터가 아닌 '관리자 검토 후보'로 대시보드에 표시합니다.

## 3. CoT(Chain of Thought) 추론 필드 추가
AI의 판단 근거를 투명하게 공개하여 정확도를 높이고 디버깅을 용이하게 합니다.
- **방안**: 결과 JSON에 `reasoning` 필드를 추가하여 "왜 이 코드를 선택했고, 왜 이 인물을 매칭/제외했는지" 설명하게 합니다.
- **기대 효과**: 리더보드 모델들이 스스로 자신의 논리를 검토하게 되어 '할루시네이션(환각)'이 줄어들며, 프롬프트의 약점을 파악하기 쉬워집니다.

## 4. Anti-Pattern (오답 노트) 강화
지키지 말아야 할 규칙을 명시적으로 보여줍니다.
- **방안**: 자주 발생하는 오매칭 사례를 "나쁜 예시"로 추가합니다.
- **예시**:
  - `Bad Case`: "요원이 총을 쏨" -> 매칭: `[ID of 특정 캐릭터]` (사유: 이름 근거 없는 추측 매칭 방지)

## 5. 드라마 독립성(Drama-Agnostic) 유지
- **방안**: 프롬프트 본문 내의 모든 예시는 고유 명사를 제거한 `인물 A`, `가명 X` 형태를 유지합니다. 특정 드라마의 지식은 오직 `${characterList}` 환경 변수를 통해서만 전달되도록 엄격히 분리합니다.
