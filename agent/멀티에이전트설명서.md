# 멀티 에이전트 시스템 사용 설명서

## 1. MCP 설정 파일 위치

| Agent | 설정 파일 경로 |
|-------|---------------|
| Gemini | `~/.gemini/settings.json` |
| Codex | `~/.codex/config.toml` |
| Claude | `<repo>/.mcp.local.json` (권장) |

**공통 MCP 서버 (5개):**
- `filesystem` - 파일 읽기/쓰기
- `memory` - 지식 그래프 저장
- `github` - GitHub API
- `terminal` - 터미널 명령 실행
- `notion` - Notion API

---

## 2. MCP 설치/로컬 설정

- 공통 설치 스크립트: `bash fivecircles/agent/scripts/setup-mcp.sh`
- 스크립트가 `.mcp-env.sh`와 `.mcp.local.json`을 생성(둘 다 ignored).
- 토큰과 `NOTION_MCP_PATH`를 `.mcp-env.sh`에 채우고 `source ~/.zshrc`로 로드.
- Notion MCP는 로컬 설치가 필요함. 각자 `NOTION_MCP_PATH`를 실제 경로로 설정.
- `.mcp.local.json`에서 `filesystem`/`notion` 경로를 사용자 환경에 맞게 수정.
- `.mcp.json`은 템플릿이며, 개인 설정은 `.mcp.local.json`만 수정.

## 3. 에이전트 역할 (Team C 기준)

| 역할 | 에이전트 | 담당 |
|------|---------|------|
| **Planner** | Gemini | 작업 분배, 조율, 전체 계획 |
| **Coder** | Claude | 코드 구현 |
| **Ops** | Codex | 배포, Git, 문서 편집 |
| **Reviewer** | Claude | 코드 리뷰, 테스트 |

---

## 4. 콜라보 운영 절차 (요약)

- **작업 시작 전**: `sync.md`, `queue.json`, `locks/` 확인 후 필요한 경우 락 생성
- **작업 진행 중**: 상태 변경은 `queue.json`, 메시지는 `sync.md`의 담당 섹션에 기록
- **리뷰/테스트 요청**: `queue.json` status를 `review`로 변경하고 `sync.md`에 알림
- **작업 종료**: 락 해제 → `sync.md` 업데이트 → `queue.json` 상태 반영
- **상세 규칙**: `fivecircles/agent/collaboration-protocol.md` 기준

## 8. 병렬 작업 방법

```bash
# 터미널 1: Planner
cd <repo> && agent-plan

# 터미널 2: Coder
cd <repo> && agent-code

# 터미널 3: Ops
cd <repo> && agent-codex

# 터미널 4: Reviewer
cd <repo> && agent-review
```

각 에이전트는 독립적인 MCP 인스턴스를 실행하므로 충돌 없음.
