## 결정안: 운영 정책 v0.1 (고정)

### 0) 우선 고정 원칙 (2026-02-26)

1. **Q20(Quick20)을 축 설정/커버리지 기준으로 먼저 고정**
2. **SPO는 기존 role 계약(`INVOLVED/SUBJECT/OBJECT`)을 우선 적용**
3. **predicate는 현재 운영중인 `PredicateCode`/`PredicateGroup` 기준으로 정합**
4. **DB 최소 변경**: 신규 relation type/메타 컬럼 증설은 보류하고, 기존 코드/그룹/키워드로 먼저 커버리지 확보

### 정합성 고정(필수, REVEALS 문서 기준)
- strict 정답 선택은 사실 이벤트(`event`) strict-first로만 수행한다.
- `event_reveal`/`reveal_type(HINT|CONFIRM)`는 WHY/근거 강도 표시에만 사용한다.
- strict miss 상태에서 reveal/probe hit만으로 `ANSWERED` 승격을 허용하지 않는다.
- canonical 기준:
  - `fivecircles/architecture/specs/reveals/reveal-evidence-label-policy.md`
  - `fivecircles/architecture/specs/reveals/reveals-classification.md`
  - `fivecircles/architecture/specs/reveals/reveals-routing-mvp-and-v3.md`

### 1) 저장(Write) 정책

1. **정답 저장소는 SQL 하나**

   * `event`
   * `event_character(role)`
   * `event_reveal`
   * `event_relation(PRECEDES)`
2. RDF는 **SQL에서 자동 투사되는 Read-only View**

   * RDF에만 존재하는 사실 금지 (드리프트 방지)

### 2) 조회(Read) 정책

1. **기본 API는 전부 SQL + 코드**

   * 리스트/정렬/K게이트/페이지네이션: SQL
   * PRECEDES 도미노: 코드 BFS (hop/max_nodes 고정)
2. **SPARQL은 ‘고급 검색/근거 그래프’ 전용**

   * SPO 패턴(2개 이상 고정) 검색
   * reveals 근거(단서) 펼치기
   * hop 2~3 고정 짧은 경로 탐색(옵션)

### 3) 질문 세트 기준(커버리지 벤치마크)

1. **Quick20 = 데이터구조/쿼리 커버리지 기준(벤치마크)**
2. **Production15 = Quick20 타입 + 파라미터 프리셋(UI 버튼)**
3. **Expansion100 = 회귀테스트 풀(새 쿼리타입 금지, 조합만)**
