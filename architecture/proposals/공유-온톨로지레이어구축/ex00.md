Rebuild Plan (review 포함, 스펙 정합성 최우선)

  0) 기준 스펙 재확인

  - 요구사항: “탐색(후보 확장)”과 “노출(보수적 필터)” 분리 (notion-origin-requirements)
  - 온톨로지: REVEALS는 설명 근거용, 탐색은 보수적 (notion-origin-ontology-layer)
  - ERD: event_relation/type, event_reveal 구조 고정 (notion-origin-erd)
  - 컨벤션: Feign, DTO/Swagger, ApiResponse 유지 (docs/BACKEND_CONVENTION, common)

  1) 탐색/노출 분리 구현

  - 탐색 단계: BFS 확장 유지 (현재 구현)
  - 노출 단계: 반환 직전 “최종 게이트” 추가
      - uptoEpisode (K) 기준으로 안전 필터 적용
      - 최소 기준: episode_start <= K (또는 episode_end <= K로 엄격화)
      - K 미지정 시: 안전 기본값(예: K=0) or filterMode=SAFE로 제한
  - 정책 연동 업그레이드:
      - spoiler-policy-service 호출로 spoiler/reason 태깅 옵션 추가
      - 기본 모드는 차단/필터, 필요 시 **설명용(revealType)**만 표시

  2) REVEALS 안전성 잠그기

  - BFS 확장에서 relation type 필터 도입:
      - 기본: PRECEDES/INVOLVES(또는 RELATED)
      - REVEALS는 explain-only (노출 결과에는 직접 섞지 않음)
  - 이를 위해 EventRelationMapper에 type IN (...) 필터 추가

  3) 정렬 기준 고정

  - 정렬: hop distance → episode_start → episode_end → id
  - “episode 기준”을 명시적으로 고정해서 UX/정책과 일치

  4) depth 정책

  - 기본값: depth=0 or 1 (보수적)
  - 상한: depth<=2 (MVP 성능/NFR 안정성)
  - 컨트롤러에서 clamp (spec-level 상한 고정)

  5) 테스트 (리뷰의 6개 전부 충족)

  - depth=0 (직접 매칭만)
  - depth=1 (1-hop 추가, hop=0 우선)
  - 루프 그래프에서도 종료 (visited)
  - 정렬 결정성 (hop→episode_start→id)
  - K 필터(episode 범위 기준) 작동
  - REVEALS 안전성(노출 위반 없음)

  6) 문서 정합성 업데이트

  - fivecircles/architecture/specs/test-server-spec에 “테스트용 서버 연결 스펙” 명시
  - fivecircles/architecture/specs/에 탐색/노출 분리 원칙 추가
  - common 변경은 최소화 (ApiResponse 유지)

  션도 유지돼.
