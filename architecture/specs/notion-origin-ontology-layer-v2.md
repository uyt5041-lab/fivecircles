# Contextual Search & Interpretation

## 1. 온톨로지 레이어의 역할 (Why)

온톨로지는 이 프로젝트에서 지식을 더 많이 저장하기 위한 장치가 아니다.
유일한 목적은 하나다.

> "같은 단어·같은 인물·같은 사건이라도  
> **맥락이 다르면 다른 것으로 취급**하기 위해"

즉, 일반 위키가 못 하는 것을 딱 한 가지 한다:

- ❌ 키워드 매칭
- ❌ 문서 단위 탐색
- ✅ **맥락 단위 탐색 (Context-aware retrieval)**

---

## 2. 일반 위키와의 구조적 차이

### 일반 위키
- 문서 중심
- 링크는 느슨함
- "A는 B다" 수준의 정적 정보

### 이 프로젝트의 온톨로지
- **사건(Event) 중심**
- 모든 정보는 **관계(Relation)** 를 가진다
- 시간(에피소드 범위)이 **1급 속성**

여기서 온톨로지는 "철학적 완성도"가 아니라 **실용적 검색과 차단의 도구**이다.

---

## 3. 온톨로지의 최소 구성 요소 (MVP Scope)

### 3.1 핵심 노드(Node)

**Event**
- 사건의 최소 의미 단위
- 속성: `eventId`, `eventType` (controlled), `episodeStart`, `episodeEnd`, `summary`

**Character**
- 기존 도메인 모델과 동일
- 온톨로지에서는 **행위 주체**로만 사용

---

### 3.2 핵심 관계(Relation)

**INVOLVES**
- Event ↔ Character
- "이 사건에 이 인물이 관여한다"

**REVEALS**
- Event → Character / Attribute
- "이 사건을 통해 무엇이 드러난다"
- ⚠️ **스포일러 핵심 관계**

**PRECEDES**
- Event → Event
- 시간적 선후 관계
- MVP에서는 자동 계산 안 함, 명시된 경우만 사용

---

## 4. 온톨로지가 사용되는 지점 (Where)

### 4.1 Q&A 맥락 검색 (핵심 차별점)

**사용자 입력:**
"주인공이 처음 배신당한 장면이 언제였지?"

**일반 검색:**
- "배신" 키워드 포함 문서 나열

**온톨로지 기반 처리:**
1. 입력 → Event 후보 추출
2. Event의 episodeStart~End 확인
3. 사용자 시청 상태와 비교
4. 결과 반환

👉 문서를 찾는 게 아니라, **사건을 찾는다**

---

### 4.2 스포일러 차단의 근거로 사용

온톨로지는 "왜 차단했는지"를 설명할 수 있게 만든다.

예시:
> "이 정보는 Event X(7화)에서 REVEALS 관계로 연결되어 있습니다.  
> 현재 시청 상태(5화) 기준으로 차단되었습니다."

이건 AI 설명이 아니라 **그래프 관계 설명**이다.

---

### 4.3 메인 페이지의 '안전한 요약' 생성

- 캐릭터 요약 = Episode <= K인 Event들의 요약 집합
- 이후 Event는 제외

온톨로지는 **"무엇을 빼야 하는지"**를 정확히 알려준다.

---

## 5. 구현 전략 (How, 현실적인 방식)

### 5.1 처음부터 그래프 DB 쓰지 않는다

**MVP 원칙 준수.**

초기 구현:
- RDB 테이블로 관계 저장
- `event_character`, `event_relation`, `event_reveal` 테이블

**그래프처럼 사용만 한다.**

---

### 5.2 Wiki Submission → Event 변환 규칙

- Submission 승인 시 Event 자동 생성
- source_type = 'WIKI', source_id = wiki_submission.id

---

## 6. 명확한 범위 제한 (중요)

다음은 **의도적으로 하지 않는다**:

- ❌ 자동 인과 추론
- ❌ 복합 감정/해석 온톨로지
- ❌ 세계관 전체 모델링
- ❌ 그래프 탐색 최적화

이 프로젝트의 온톨로지는:
> "검색 정확도와 스포일러 안전성을 동시에 확보하기 위한  
> **최소한의 관계 모델**"

그 이상도, 이하도 아니다.

---

## 7. 성공 기준 (Ontology Layer)

온톨로지 레이어는 다음이 가능하면 성공이다:

1. **같은 질문이라도** 키워드가 아니라 **사건 기준**으로 응답한다
2. **차단 시** "왜"를 **관계와 에피소드로 설명**할 수 있다
3. **개발자가** "이건 온톨로지라서 이렇게 동작한다"고 명확히 설명할 수 있다
