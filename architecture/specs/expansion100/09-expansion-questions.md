## 확장 질문 작성 워크플로우 (고정)

아래 순서를 모든 인스펜션/확장 질문 문서에 공통 적용한다.

1. 질문 정의
2. 정답/맥락 도미노 작성 (웹 검증 + 출처 링크 기록)
3. 앵커 이벤트 확정 (`evidence_event_id`)
4. 실행 설계 결정 (Template 또는 RDF/SPARQL)
5. 데이터 반영 (`event`, `event_character`, `event_relation(PRECEDES)`)
6. 질문/답변 구현 (컨텍스트 기본 양방향 `causes+effects`)
7. 검증 (`Strict 결과=앵커`, `probe` 분기, `K gate`, 체인 순서)
8. 문서 동기화 (anti-halu + 템플릿 가이드 + 운영 스크립트/검증 SQL)

핵심 체크 3원칙
- `strict-first`: strict 0건이면 probe로만 판정
- `K gate`: 절대회차(`safeUpToEpisode`) 기준 고정
- `bidirectional context`: 기본은 원인+결과 동시 조회
